# Domain Driven Design

## Goal
Apply Domain-Driven Design with bounded contexts, aggregates, value objects, and ubiquitous language.

## Instructions
1. Analyze the current project context and requirements
2. Apply industry best practices for this domain
3. Generate production-ready, well-tested implementation
4. Include proper error handling and edge case coverage
5. Document decisions and provide usage examples
6. Verify security implications of the implementation

## Constraints
- Follow existing project patterns and conventions
- Never expose secrets, tokens, or credentials
- Handle all failure modes gracefully
- Optimize for maintainability over cleverness
- Include meaningful error messages for debugging
- Add inline documentation for complex logic

## Examples
Refer to the project codebase for existing patterns and conventions.
